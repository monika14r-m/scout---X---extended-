Real simulation.

SCOUT-X is a simulation-first UAV security project built around an Iris aircraft in Gazebo Sim, ArduCopter SITL, MAVProxy and a Python/MAVLink monitoring layer.

Important: This project page does not fake a drone animation or pretend to stream a live simulator. Gazebo and ArduPilot run on the project workstation. The files below launch that actual simulation. Recorded Gazebo footage will appear here only after it has been captured from a real run.

Project scenarios

01 · GCS command execution & logging

Send a confirmed command to the SITL vehicle, observe the Iris response in Gazebo, monitor telemetry and record the operation.

02 · GCS signal / packet loss

Exercise the SCOUT-X application-level heartbeat timeout, monitor the loss event and request the configured SITL response. This is not a physical radio outage.

03 · Critical attack / hijack indicator

Record a simulated critical incident, capture a telemetry snapshot and lock the demo controller. No destructive wipe is performed.

Additional · GPS anomaly

Compare live SITL reference telemetry with a synthetic shadow-GPS offset. The synthetic value is not injected into the flight controller.

Launch the actual Gazebo simulation

1
Start Gazebo Sim 8
cd ~/scout---X---extended-
bash simulation/run_gazebo.sh
2
Start ArduCopter SITL in another Ubuntu terminal
cd ~/scout---X---extended-
bash simulation/run_sitl.sh

At MAV>, verify that output includes 127.0.0.1:14550. Add it with output add 127.0.0.1:14550 if required.

3
Connect SCOUT-X telemetry monitor
cd ~/scout---X---extended-
source ~/venv-ardupilot/bin/activate
PYTHONPATH=live_demo python3 -m scoutx_live status --connect udp:127.0.0.1:14550
4
Run a project case
bash simulation/run_case.sh case1-command
bash simulation/run_case.sh case2-gcs-loss
bash simulation/run_case.sh case3-critical-hijack

Run one case at a time. Case 1 requires typing SITL to confirm that the target is the simulator.
